# 打字模型

planner 把文本变成一条事件时间线，每个事件带 `gap`，即它之前要等待的毫秒数。`humantype plan ... --timeline` 会把它打印出来。

## 默认值模拟的是谁

一位整天打字、英语为第二语言但很流利的打字员，比如在工作中写英文的工程师。参照的是 Dhakal 等人的 *Observations on Typing from 136 Million Keystrokes*，CHI 2018（168,960 名参与者）：

| 指标 | Dhakal 等人 | human-typing 默认值 |
| --- | --- | --- |
| 速度 | 平均 51.56 WPM（SD 20.2） | 有效速度 60 WPM（p10-p90 55-66） |
| 按键间隔 | 平均 239 ms；约 78 WPM 以上为 122 ms | 连击 140 ms（86 WPM），词首更慢 |
| Backspace 占按键的比例 | 总体 6.3%，26 WPM 以下 9.05%，78 WPM 以上 3.4% | 3.7% |
| 每个字符的按键数 | 1.173 | 1.08 |

默认值是在一个 150 个字符的商务句子上跑 500 个 seed 测得的。论文没有区分母语与非母语（样本中 85% 是英语母语者），所以第二语言的影响是建模得到的，而不是拟合出来的：常见词保持快速，而长的生僻词（7 个以上字母，不在常用词表里）词首慢 1.35 倍，打字慢 1.12 倍，思考停顿多 2.5 倍，打错多 1.4 倍。

`--typo 0.03` 时 Backspace 占 5.3%，接近研究的平均值。有效速度大致与 `--wpm` 成线性关系：`--wpm 75` 约为 52 WPM。

## 逐键时间

每个间隔取自以连击间隔（`60000 / (wpm * 5)` ms）为中心的 log-normal 分布，再按下表调整：

| 条件 | 效果 |
| --- | --- |
| 常见 bigram（th、er、in 等） | x0.65 |
| 重复字母 | x0.8 |
| 大写字母 | Shift 额外 +40-110 ms |
| 数字 | x1.3 |
| 符号 | x1.5 |
| 空格 | x1.1-1.5 |
| 单词的首字母 | x1.3-2.0 |
| `,` `;` `:` 之后 | 额外停顿 |
| `.` `!` `?` 之后 | 更长的停顿 |
| 换行之后 | 0.5-1.5 s |

## 打错与修正

打错有三种：QWERTY 上的相邻键（字母只会错成字母）、颠倒的两个字母或重复字母。打字员在多打 0-2 个字母后发现，停顿 200-600 ms，退格后重打。按 `--retype` 的概率，一个打完的词会被删掉重打；按 `--think` 的概率，一个词前会有 0.5-1.8 s 的停顿。这些都不会出现在被粘贴的 span 里。

## 粘贴的 span

粘贴前要等 1.5-5 s（切到编辑器、找到名字、复制、切回来），然后通过页面 JavaScript 把 span 写入剪贴板，在同一批里按 Ctrl+V（planner 运行在 macOS 上时用 Cmd+V；尚未在 macOS 上测试），再等 0.3-1 s 才恢复打字。剪贴板写入紧贴在粘贴键之前，因为曾经把写入放在前一个 agent 回合，结果用户在中间复制了别的东西，写入输掉了这场竞争。

## CJK 文本

中文、日文和韩文要经过输入法，因此不能逐键发送。它们按 1-3 个字符一块发送，块与块之间间隔 0.35-1.1 s。

## 后端开销

每个浏览器操作都有一个下限：工具自身要花的时间。planner 会从每个间隔里减掉它，让页面看到的就是计划的时间。

| | Claude in Chrome | Browser MCP |
| --- | --- | --- |
| 单次操作的下限 | ~18 ms | 字母约 50 ms |
| 等待精度 | 相对 plan 中位数 +10 ms，最大 +20 ms（48 个间隔） | 相对 plan +10 到 +20 ms |
| Backspace | 与一个字母相同 | `press Backspace` 阻塞约 470 ms，所以连续的退格至少间隔约 530 ms |

两者产生的 keydown、input 和 paste 事件都是 `isTrusted`；粘贴到达时 `inputType: insertFromPaste`。在 Windows 11 桌面、Chrome stable 上实测。
